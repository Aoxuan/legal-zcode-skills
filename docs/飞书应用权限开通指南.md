# 飞书应用权限开通指南

> 致：飞书管理员 / IT
> 目的：让「合同审批风险预警」技能能用应用身份读取审批、回填风险评级与报告并同意放行；并让申请人在合同审批表单里就能搜企业。
> 你要配合 **三件独立的事**，做完一件不等于另一件生效：


| 工作               | 在哪做    | 目的                | 怎么算做完                    |
| ---------------- | ------ | ----------------- | ------------------------ |
| **工作一：开通自建应用权限** | 开发者后台  | 技能能用应用身份读审批、同意任务并回填表单 | 应用五条 scope 已开通且最新版本已发布通过 |
| **工作二：调整合同审批表单** | 审批管理后台 | 申请人能在表单里搜企业（客户/供应商/达人企业名称） | 外部选项单选控件配好并发布审批定义新版本 |
| **工作三：审批流加「系统风险预审」节点** | 审批管理后台 | 技能有权回填评级/附件并放行 | 预审节点+可编辑控件配好并发布新版本 |


两件事在两个后台、走两套发版，互不影响：

- 工作一在「开发者后台」发**应用版本**；工作二在「审批后台」发**审批定义版本**。
- 工作一不需要机器人、不需要消息事件、不需要 webhook、不需要公网地址（技能是定时轮询，应用身份调用）。
- 工作二要填的 URL / Token 是**我方已部署的中转适配器**，不是企查查开放平台地址，也不是 App Secret。企查查账号密钥只放在我方运行机的 `.env`，不进飞书后台。

---

## 工作一：开通自建应用权限

### 1.1 创建或复用自建应用

1. 打开 [open.feishu.cn](https://open.feishu.cn)，登录进入「开发者后台」→「企业自建应用」。
2. 可复用现有自建应用，或新建一个。建议命名清晰，例如「法务合同小助手」。
3. 在「凭证与基础信息」记下 **App ID** 与 **App Secret**，私发给 法务 写入技能的 `.env`。



### 1.2 开通权限（权限管理 → 添加应用身份权限）

只需这五条：


| 权限 scope                          | 用途             | 必需  |
| --------------------------------- | -------------- | --- |
| `approval:approval.list:readonly` | 查询审批实例列表（兼容保留） | 必需  |
| `approval:approval:readonly`      | 读取审批实例详情与表单    | 必需  |
| `approval:task`                   | **同意任务并回填表单控件（本技能核心，缺了无法回填评级/附件）** | 必需  |
| `approval:task:list_by_user`      | 查询预审账号的待办任务 | 必需  |
| `contact:user.id:readonly`        | 获取用户 ID：手机号/邮箱反查（用于预审账号） | 必需  |


> 预审账号写在 `.env` 的 `FEISHU_APPROVER_USER_ID`（`_TYPE` 指明 `user_id`/`open_id`）。没有现成 ID 时，用已开通的 `contact:user.id:readonly` 按手机号/邮箱反查后再写入 `.env`。反查时把该账号纳入应用「通讯录权限范围」，范围外查不到。





### 1.3 保存 → 创建版本 → 发布 → 审批

> 改权限后**必须**走完发版流程，否则不生效。

1. 权限页点「保存」。
2. 应用首页「创建版本并发布」。
3. 租户管理员审批通过。
4. 「应用可用范围」配置：法务部 + 需要跑技能的电脑对应账号（技能用应用身份调用，可用范围要覆盖应用本身）。



### 1.4 把以下信息交给 法务（写入 `.env`）


| 项                                     | 怎么取                                           |
| ------------------------------------- | --------------------------------------------- |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 凭证与基础信息页                                      |
| `FEISHU_APPROVAL_CODES`               | 打开合同审批定义，浏览器地址栏 URL 里的 `approvalCode`；多个用逗号分隔 |
| `FEISHU_FIELD_COMPANY`                | 表单里候选企业控件的控件名，逗号分隔（现在是「客户名称,供应商名称,达人企业名称」，见工作二）。 |
| `FEISHU_FIELD_RATING` / `FEISHU_FIELD_ATTACHMENT` | 回填控件名：默认「企业风险评级」；附件配稳定前缀「风险报告附件」即可（见工作三）。 |
| `FEISHU_APPROVER_USER_ID` / `FEISHU_APPROVER_USER_ID_TYPE` | 「系统风险预审」节点审批人的账号 ID 及类型（`user_id` 或 `open_id`）。没有现成 ID 时用 `contact:user.id:readonly` 按手机号/邮箱反查（法务可在对话里把号码/邮箱交给 AI 代查代写） |





### 1.5 如果预审跑失败

常见三种情况：

1. **查询待办失败/400**：`FEISHU_APPROVER_USER_ID` 与 `_TYPE` 不匹配（比如填了 user_id 却标成 open_id）。核对后重跑。
2. **提示无权限/同意任务失败**：回到 1.2 确认五条 scope 都开通且已发版通过；确认应用可用范围覆盖。
3. **放行成功但表单没写进去**：确认【企业风险评级】【风险报告附件】两个控件已在「系统风险预审」节点设为可编辑（见工作三）。

把报错原文发给 IT，不要自己改。

### 1.6 工作一怎么检验

1. 开发者后台该应用「权限管理」能看到这五条已开通，且**最新版本已发布通过**。
2. 把 App ID / App Secret / `approvalCode` / 预审账号 ID 私下交给法务写入 `.env` 后，在技能目录跑 `py scripts/poll.py check`，输出 `ok` 为 `true`。
3. 有一张待审批合同时，法务干跑（`FEISHU_COMMENT_DRY_RUN=1`）或正式轮询一次：能读到表单里的对方企业；正式跑后审批单里出现回填的评级与「风险报告附件」，任务被同意放行。读不到 / 写不了，按 1.5 排查，**不要去改表单**。

## 工作二：调整合同审批表单

> 在「审批管理后台」编辑「合同申请」审批定义，**不要和开发者后台混在一起**。
> 把表单里的企业控件（客户名称 / 供应商名称 / 达人企业名称）接上我方已部署的中转适配器（外部选项搜索）。涉及控件用**同一串 Token**。

适配器地址（已部署，照填即可）：

- 企业名称搜索（名称｜信用代码｜法人）：`http://101.96.217.199:12000/feishu/approval/external-options/company`
- 仅企业名（只要工商全称）：`http://101.96.217.199:12000/feishu/approval/external-options/company-name`
- 企业风险评级（**已下线**，见 2.2，无需配置）：`http://101.96.217.199:12000/feishu/approval/external-options/risk`

Token：麦麦熊猫IT提供，与适配器 `.env` 的 `FEISHU_EXTERNAL_OPTIONS_TOKEN` 同一串；两个控件填**同一串**。不要写真实值进截图、不要发聊天群。

### 2.1 企业控件：单选 + 外部数据源（客户名称 / 供应商名称 / 达人企业名称）

- 三个企业控件同样配法（以「客户名称」为例；「供应商名称」「达人企业名称」同理）。三者互斥，申请人按合同类型只会填其中一个。
- 类型：单选；**必填**；禁止手填自由文本。
- 选项来源：使用外部选项；处理方式 **V2（支持模糊、分页搜索）**。
- URL：`http://101.96.217.199:12000/feishu/approval/external-options/company`
- Token：IT 提供的那一串（与适配器一致）
- Key：**留空**（本期不加密）

**2.1 怎么检验**

- 设计器点「校验接口」：能通过即可（空关键词会回空列表，这是正常的，不要当成失败）。
- 保存后用测试账号**真发起一张合同审批**（不要只信校验按钮）：在「客户名称」输入「顶呱呱」或「讯格得」，应弹出候选，展示为 `名称｜信用代码｜法人`，点选一家后能带上选中值。
- 失败常见原因：URL 填成企查查地址、Token 与适配器不一致、审批定义未发版、适配器关机。把报错原文给 IT，不要自己改 Token 以外的项。



### 2.2 表单内实时风险评级 —— 已下线（2026-09-04）

原方案（「企业风险查询」单选联动 `/risk`，提交前实时查风险）**已下线**：风险评级改为由「合同审批风险预警」技能在审批流里**轮询回填**（见工作三），申请人提交后自动完成，表单里不再需要风险控件、也不再产生提交时的查询费用。

历史配置无需删除，但不要再新增。

### 2.3 其他审批单只要企业名（不要信用代码/法人）

另配一个单选 + 外部选项 V2，**不要改**合同审批里已有的 `/company`：

- URL：`http://101.96.217.199:12000/feishu/approval/external-options/company-name`
- Token：与上面同一串；Key 留空
- 下拉只显示工商全称，点选后控件存的也是这个名字

**怎么检验**：设计器「校验接口」能通过即可。真发起时输入「顶呱呱」，候选应只有企业名，没有 `｜信用代码｜法人`。

### 2.4 工作二做完，把这些交给 法务/麦麦熊猫IT

- 企业控件的**最终显示名**（如「客户名称,供应商名称,达人企业名称」）。
- 写入 `.env` 的 `FEISHU_FIELD_COMPANY`（按上一步显示名填，逗号分隔）。
- 浏览器「合同审批」URL 的 `definitionCode`（地址栏里取，多个逗号分隔）。

## 工作三：审批流加「系统风险预审」节点（回填评级/报告并放行）

> 同样在「审批管理后台」编辑合同审批定义。这一步没做，技能无处回填字段（飞书原生审批只能在「同意某审批任务」时写表单控件值）。

1. **新增审批节点**「系统风险预审」：审批人 = 预审员工账号（一个固定员工账号，把它的 ID 交给 IT 写 `.env`），排在法务节点之前。
2. 在该节点的「字段权限」里：
   - 【企业风险评级】（文本控件）：设为**非必填 + 可编辑**（该控件已有则复用，没有就新增一个文本控件）。
   - **新增附件控件「风险报告附件」**：设为**可编辑**。控件名完整包含「风险报告附件」即可（例如「风险报告附件（请勿上传文件，由法务AI智能体审批后上传）」），括号说明可按需调整，技能按前缀模糊匹配。
3. 「合同附件」等申请人控件不需要对预审节点开放编辑。
4. **发布审批定义新版本**，未发版不生效。

**怎么检验**：提交一张测试合同（企业控件任选一家公司）→ IT 跑一次 `py scripts/poll.py poll` → 审批单里【企业风险评级】出现「低风险 / 中风险，详见风险报告附件 / …」，「风险报告附件」出现一份 Excel，预审任务被自动同意放行。申请人若误往「风险报告附件」传了文件或往评级里写了字，预审时会一并清除（这两个位置只保留 AI 写入的内容）。

## 安全提示

- App Secret 是密钥，只私发给 法务 写入运行机的 `.env`，不进 git、不进聊天群、不截图。
- 飞书表单里填的 Token 是我方适配器的校验串，**不是企查查 Key，也不是 App Secret**；同样不要截图、不要填进聊天群。
- 应用可用范围按需收敛到法务 + 跑技能的账号，不要开全员。
- 不开通本技能用不到的权限。
