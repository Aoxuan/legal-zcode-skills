# 飞书应用权限开通指南

> 致：飞书管理员 / IT
> 目的：让「合同审批风险预警」技能能用应用身份读取审批、在审批评论区写风险预警。
> 本技能**不需要机器人、不需要消息事件、不需要 webhook、不需要公网地址**。只要三条审批权限。

---

## 一、它能做什么

技能用飞书自建应用的 `tenant_access_token`（应用身份）做两件事：

1. 读取「待审批」的合同审批实例和表单里已选定的对方企业。
2. 在该审批实例的**评论区**写一条风险预警 + 上传一份 Excel 附件。

全程应用身份，不模拟某个用户，不需要长连接进程。

---

## 二、创建或复用自建应用

1. 打开 [open.feishu.cn](https://open.feishu.cn)，登录进入「开发者后台」→「企业自建应用」。
2. 可复用现有自建应用，或新建一个。建议命名清晰，例如「法务合同风险预警」。
3. 在「凭证与基础信息」记下 **App ID** 与 **App Secret**，私发给 IT 写入技能的 `.env`，不要外传、不要入库。

---

## 三、开通权限（权限管理 → 添加应用身份权限）

只需这三条：

| 权限 scope | 用途 | 必需 |
|---|---|---|
| `approval:approval.list:readonly` | 查询审批实例列表（扫待审批） | 必需 |
| `approval:approval:readonly` | 读取审批实例详情与表单 | 必需 |
| `approval:approval` | 创建审批评论（含上传附件） | 必需 |

**不要**开通：机器人能力、`im:message`、消息事件订阅、webhook、云文档权限、通讯录权限。本技能用不到，开了反而扩大暴露面。

---

## 四、保存 → 创建版本 → 发布 → 审批

> 改权限后**必须**走完发版流程，否则不生效。

1. 权限页点「保存」。
2. 应用首页「创建版本并发布」。
3. 租户管理员审批通过。
4. 「应用可用范围」配置：法务部 + 需要跑技能的电脑对应账号（技能用应用身份调用，可用范围要覆盖应用本身）。

---

## 五、把以下信息交给 IT（写入 `.env`）

| 项 | 怎么取 |
|---|---|
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 凭证与基础信息页 |
| `FEISHU_APPROVAL_CODES` | 打开合同审批定义，浏览器地址栏 URL 里的 `approvalCode`；多个用逗号分隔 |
| `FEISHU_FIELD_COMPANY_NAME` | 表单里对方企业名称控件的「名称」（现在是「对方单位名称」）；若名称有重名，改填控件的 widget id（审批定义编辑页查看） |
| `FEISHU_FIELD_CREDIT_CODE` | 对方企业信用代码控件标识。当前信用代码藏在「对方单位名称」外部选项的选项 id 里，与名称同控件，故此项与 `FEISHU_FIELD_COMPANY_NAME` 填同一个控件名 |
| `FEISHU_FIELD_LEGAL_PERSON` | 对方负责人控件名（现在是「对方负责人」） |
| `FEISHU_COMMENT_USER_ID`（可选） | 部分租户写评论必须指定发表人。需要时给一个法务账号的 `open_id`；不要时留空 |
| `FEISHU_COMMENT_USER_ID_TYPE`（可选） | 默认 `open_id`，可填 `user_id` / `union_id` |

---

## 六、如果写评论失败

常见两种情况：

1. **提示要发表人**：该租户要求评论指定发表人。给一个法务账号的 `open_id`，IT 写入 `FEISHU_COMMENT_USER_ID`。
2. **提示无权限**：回到第三步确认三条 scope 都开通且已发版通过；确认应用可用范围覆盖。

把报错原文发给 IT，不要自己改。

---

## 七、关于「审批表单里搜企业」

在审批申请表单里选对方企业，走的是另一个公网适配器（外部数据源），**不是**这个 zcode 技能，本指南不展开。只需知道：选企业仍在飞书表单里完成，技能只负责读已选好的企业和写评论。

---

## 八、安全提示

- App Secret 是密钥，只私发给 IT 写入运行机的 `.env`，不进 git、不进聊天群、不截图。
- 应用可用范围按需收敛到法务 + 跑技能的账号，不要开全员。
- 不开通本技能用不到的权限。
