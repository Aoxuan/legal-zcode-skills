# 配置说明

> 本文档面向**法务**和**IT**。法务只需看「法务要做的」；其余配置项由 IT 准备好并填进 `.env`。
> 真实密钥只放在运行电脑的 `.env` 里，**不入库、不外传、不截图发群**。

---

## 一、法务要做的（很简单）

1. 确认电脑装好 zcode 并登录。
2. 确认电脑装好 **Python 3.11**。没有就让 IT 装（见下文「装 Python」）。
3. 确认 zcode「技能」页里出现这两个技能：
   - `legal-company-query`（企业风险查询）
   - `legal-approval-risk`（合同审批风险预警）
4. 从 IT 那里**私下**拿到一份已填好的 `.env` 文件，分别放到两个技能文件夹里（IT 会告诉你具体路径）。**不要自己填密钥**，也不要把这份文件外传。

装完、放好 `.env` 后，让 IT 或自己跑一次自检（见下文「自检」）。通过就能用了。

---

## 二、装 Python 3.11（没有 Python 时）

Windows 用 `py`，macOS 用 `python3`。先探测：

```
Windows：py --version
macOS：python3 --version
```

输出含 `3.11` 就跳过本节。

### Windows

1. 双击官方安装包 `python-3.11.x-amd64.exe`（IT 提供）。
2. 勾选 **Add python.exe to PATH**。
3. 选当前用户安装（一般不必管理员）。
4. **新开**一个终端，跑 `py --version`，应看到 3.11。

### macOS

- 官方安装包：[Python 3.11 macOS](https://www.python.org/downloads/release/python-3119/)，选 macOS 64-bit universal2 installer，按向导装。
- 或 Homebrew：`brew install python@3.11`。
- 装完新开终端跑 `python3 --version`。

---

## 三、装技能依赖（每个技能都要做一次）

在**每个技能文件夹**（有 `requirements.txt` 的目录）里执行。先判断外网是否通，不通走内网代理。

外网通：

```
Windows：py -m pip install -r requirements.txt
macOS：python3 -m pip install -r requirements.txt
```

外网不通（内网代理）：

```
py -m pip install -r requirements.txt -i http://docker-proxy.xgate.com/simple
```

依赖：requests、python-dotenv、openpyxl、pymysql。

---

## 四、自检

放好 `.env`、装好依赖后，在每个技能目录跑一次自检。通过才能用。

```
企业风险查询：    py scripts/query.py check
合同审批风险预警： py scripts/poll.py check
```

输出里 `ok` 为 `true` 就通过。失败把提示原文发给 IT，不要自己改。

---

## 五、`.env` 里要填什么（IT 准备，法务不用自己填）

每个技能目录里把 `.env.example` 复制为 `.env`，按下面填。**推荐 IT 私下发一份已填好的 `.env`，法务只负责放到技能目录并保密。**

### 两个技能都要填

| 项 | 人话 | 谁给 |
|---|---|---|
| `QCC_APP_KEY` / `QCC_SECRET_KEY` | 企查查**主账号**密钥（用于 856 三要素核验、739 异常） | 企查查开放平台 |
| `QCC_APP_KEY_MONICA` / `QCC_SECRET_KEY_MONICA` | 企查查 **Monica 账号**密钥（固定用于 886 搜索、2006 风险、887/888/889 涉诉） | 企查查开放平台 |
| `MYSQL_HOST` / `MYSQL_PORT` / `MYSQL_USER` / `MYSQL_PASSWORD` / `MYSQL_DB` | 查询结果存档库的连接信息 | IT / DBA |

> **两套企查查 Key 都要填，只填一套会查不全。** 主账号跑 856/739，Monica 跑 886/2006/887/888/889。生产账号若已开通全部接口，可只填主账号、删掉 Monica 两项。

### 仅合同审批风险预警（legal-approval-risk）还要填

| 项 | 人话 | 谁给 |
|---|---|---|
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书自建应用凭证 | 飞书管理员（按《飞书应用权限开通指南》开好后给） |
| `FEISHU_APPROVAL_CODES` | 合同审批定义 code（审批后台网址里的 approvalCode，多个逗号分隔） | 飞书管理员 |
| `FEISHU_FIELD_COMPANY` | 表单里「对方企业」那一个外部选项的控件名（现在是「对方单位名称」）。技能从这一格同时取出名称、信用代码、法人。不读「对方负责人」。 | 飞书管理员 |
| `FEISHU_COMMENT_USER_ID` | 写评论的发表人 open_id。租户写评论必须带此项；没有现成 open_id 时，用已开通的 `contact:user.id:readonly` 按手机号/邮箱反查后再写入 `.env` | 飞书管理员 |
| `FEISHU_COMMENT_USER_ID_TYPE` | 默认 `open_id` | 飞书管理员 |

可选运行参数（一般不用动）：

- `FEISHU_QUERY_WINDOW_DAYS`：轮询时间窗，默认 30 天（飞书上限 30）。
- `FEISHU_COMMENT_DRY_RUN=1`：只取风险、不写评论（验收用）。
- `QCC_DATA_DIR`：运行时数据目录，默认写技能内 `data/`。
- `QCC_ENV_FILE`：指定 `.env` 路径。

## 六、风险分级规则（法务关心的口径）

当前规则按 `05-企查查接口数据法务确认表.xlsx`「风险分级规则建议稿」落地，版本 `legal-draft-2026-08-13`：

- **高风险**：失信/被执行/破产/限高/股权冻结/严重违法、行政处罚（法务裁定=高）、三要素不一致、登记状态含吊销/注销/停业/撤销/清算中；裁判文书累计≥10 或近 12 个月被告≥3；开庭公告累计≥10；立案累计≥5。
- **中风险**：未移出的经营异常、环保处罚、动产抵押/股权出质/清算/欠税/税务非正常/税收违法/司法拍卖/公安通告；近 24 个月裁判文书且为被告、近 24 个月开庭公告、近 24 个月立案且为被告。
- **低风险**：以上均未命中。
- **未知**：查无此企业或数据不存在。

法务裁定栏除「行政处罚」外尚未勾选，其余按建议稿执行。要改阈值找法务负责人 + IT，改 `scripts/qcc/grading.py` 的 `DEFAULT_RULES`，不要在 `.env` 里改。

## 七、安全红线

- `.env`、真实密钥、企业快照、Excel、审计日志、`data/state.json` **不入 git、不外传**。
- 企查查数据仅用于内部风控审批，**不得二次分发**。
- `.env.example` 里是空模板，可以入库；`.env` 是真密钥，绝不入库。
