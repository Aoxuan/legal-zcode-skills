# 合同台账录入技能 · 使用说明（法务版）

> 适用版本 v1.3.2。装好之后在 zcode 里**直接说话**就能用，不需要记任何命令。单号 = 审批单上能看到的那串数字（12 位，如 `202610140023`）。

## 1. 这个技能帮你做什么

你报一个审批单号，技能自动完成：

1. 找到这张合同审批，下载里面的合同 Word
2. 提取合同名称（Word 首页标题）、我方主体、相对方、金额、摘要
3. 自动区分主合同 / 子合同（补充协议、终止协议、结算单、执行单四类进子表，其余进主表）
4. 写入合同台账，回读系统生成的合同编号（`BTSP…` 自动编号，**不需要也不允许人工编号**）
5. 给你一段拟好的审批意见（`合同编号：BTSP…`），**你确认后**才替你点「同意」，并把编号写进审批意见

**同一张审批只建一次行**：录过的单号再说一遍，直接返回已有记录，不会重复占号。

**技能不做的事**：不自动盯新审批（每次都要你给单号）、不发飞书消息、不转 PDF、不盖水印、不改审批表单里的任何控件、不回收驳回产生的空号。

## 2. 日常用法（在 zcode 里说话即可）

| 你想做的 | 可以这样说 |
|---|---|
| 先预演一遍（不真写台账） | 「把 202610140023 **干跑**一遍」 |
| 录入台账 | 「把审批单 202610140023 录入台账」 |
| 放行审批 | 不用单独说——录入成功后 zcode 会把拟意见给你，你确认即可 |

一次完整交互长这样：

1. 你：`把 202610140023 录入台账`
2. zcode：写入成功，合同编号 `BTSP2026090501`（示意），拟审批意见：`合同编号：BTSP2026090501`——按这段放行吗？
3. 你：`同意`（或：`再加一句"已归档"，然后放行`——zcode 会保住合同编号那一行再拼上你的话）
4. zcode：已替你同意审批，意见已写入

**放行只发生在四个条件都满足时**（不满足时台账照写、只是不点同意，原因 zcode 会告诉你）：

- 这台电脑绑定的使用人（安装时绑过一次）是这张单**当前待办审批人**
- 该使用人在这张单上只有一条待办
- 最终意见里包含本次合同编号
- 该使用人在本机**放行白名单**内（安装时首次绑定自动建立；换绑别人需管理员操作）

## 3. 这些情况技能会「停住」（不建行、不占号）

| zcode 提示 | 原因 | 你要做的 |
|---|---|---|
| 找到 0 条或多于 1 条审批 | 单号抄错，或前后几天窗口里撞号 | 核对审批单上的单号 |
| 附件是旧版 `.doc` | Word 2003 之前格式 | **会自动处理**：技能调用本机 Word 静默转成临时副本再解析（原件不动）。前提：Windows + 已安装 Word。没装 Word、转换失败（加密/损坏）时才停住，此时手动另存为 `.docx` 重新上传 |
| 抽不出合同标题 | 首页没有可识别的标题行 | 这一行请在台账里人工建 |
| 我方主体对不上 | 审批里选的签约主体在台账表里没有对应选项 | 找台账管理员在表里加上该选项后重跑 |
| 子合同找不到主合同编号 | Word 首页没写 `BTSP…` 主合同号，或出现多个 | 检查合同首页的主合同编号是否唯一 |
| 取不到相对方主体 | 签约类型/客户/供应商全空；报错会列出依次尝试过的控件和 id（表单里填了仍停住，多半是控件 id 与审批定义不一致） | 先看审批表单企业控件是否已填；填了仍停住就把报错原文发对接人核对 |
| 合同编号没生成 / 回读失败 | 表格自动编号偶发延迟或接口抖动 | 行已建、已记防重，**稍后把同一个单号再说一遍**即可接着查编号，不会重复建行 |

## 4. 常见问题

- **录错了想重跑？** 已建的行不会自动删：联系对接人清掉本机状态记录（`data/state.json` 里对应那条）并在台账删行，然后重跑。驳回产生的空号请在台账里**人工作废**，技能不回收。
- **换电脑 / 换人使用？** 每台电脑各自安装、各自绑定使用人（安装时问一次手机号或邮箱）。放行永远以那台电脑绑定的使用人身份进行。**换绑成另一个人**必须由管理员执行 `bind-user --add`（显式加入放行白名单），直接给手机号会被拒绝；所有绑定与放行动作都留本地审计日志 `data/bind_audit.jsonl`（手机号只留掩码）。
- **现在写的是哪个台账？** 验收期间写的是**副本**台账（编号由副本生成）。切换正式台账由对接人统一改配置并通知，历史行不迁移。
- **子合同会另占一个根号吗？** 不会。子合同挂在主合同行下面，编号由表格公式生成（形如 `BTSP2026090501-BC01-202610`）。

## 5. 附：安装速查（IT / 管理员用）

1. 解压技能包到 zcode skills 目录（Windows：`C:/Users/<用户>/.zcode/skills/`）
2. 复制 `.env.example` 为 `.env`，**只需填** `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 两项（审批 code 与台账坐标已预填；`.env` 不入库、不外传）
3. 装依赖：`py -m pip install -r requirements.txt`（外网不通加 `-i http://docker-proxy.xgate.com/simple`）
4. 绑定使用人：`py scripts/entry.py bind-user --mobile <手机号>`（或 `--email <邮箱>`，二选一）。用自己的号码，在预置白名单内即直接绑定成功；换绑/新增他人需管理员 `--add`，全过程留审计日志
5. 自检：`py scripts/entry.py check` 全绿即就绪；**新开一个 zcode 会话**后技能生效

飞书应用需开通并**创建版本 → 发布 → 管理员审批**后才生效的权限：

| 权限 | 用途 |
|---|---|
| `approval:approval.list:readonly` | 按单号查审批实例 |
| `approval:approval:readonly` | 读实例和合同附件 |
| `bitable:app` | 读写合同台账 |
| `approval:task` | 同意当前待办审批 |
| `contact:user.id:readonly`（通过手机号或邮箱获取用户 ID） | `bind-user` 调用的基础权限 |
| `contact:user.employee_id:readonly`（**获取用户 user ID**） | `bind-user` 反查 `user_id` 的字段权限；注意飞书此处命名错位，认准权限名「获取用户 user ID」，与员工 ID 无关 |

另外：应用需被加为台账副本的**协作者**；审批定义需对应用可见。

**bind-user 反查得到的两个前置**（装不上先查这里）：

1. 被绑定账号必须在应用的**通讯录权限范围**内（范围外手机号/邮箱会报"查不到"）。建议管理员按《36-自建应用通讯录可见范围收缩-给管理员》把范围限定到技能使用人，这同时也是安全加固。
2. 权限开通后要**创建版本 → 发布 → 管理员审批**，只改不发版不生效。

**安装需要准备/操作的清单**（给装机人）：

| 项 | 在哪 | 说明 |
|---|---|---|
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | `.env`（唯一必填项） | 向管理员索取；审批 code、台账副本坐标已预填 |
| 绑定使用人 | `py scripts/entry.py bind-user --mobile <手机号>` | 装完先做，**用自己的手机号**。交付包已预置全体授权使用人的放行白名单，白名单内首绑直接成功；换绑/新增他人必须管理员 `bind-user --add` |
| 自检 | `py scripts/entry.py check` | 七项全绿即就绪（未绑定时录入可用、放行不可用） |

**验收期注意**：当前台账坐标是**副本**，切换正式台账由对接人统一改 `.env` 并通知；技能不会自动切。

## 6. 附：切换正式台账（对接人用，副本验收通过后执行）

前置（管理员/法务先在飞书后台做）：

1. 正式台账文档把应用加为**协作者（可编辑）**
2. 审批后台确认正式「合同审批」定义**对应用可见**
3. 正式审批表单控件与副本一致（签约主体 / 客户名称 / 供应商名称 / 概述 / 合同附件）

然后把下面整段粘贴给 zcode（AI 助手）执行：

```
把 legal-ledger-entry 从台账副本切换到正式环境（副本已验收通过）：
1. .env 审批 code 改为 DB2F122F-9823-4D8E-9D01-7CFC068472FE（后台网址里的 id 7241484543487049731 只是页面 id，不得传给任何 API）
2. .env 台账 app_token 改为 LmVHbDXpdaNTK1sTDbjceczrnkh，主表 id tbln45WEECZDdHC3
3. 控件 id 无需手改：技能按 .env 审批 code 自动切换「供应商名称」「风险报告附件」两个 id（2026-10-26 已并集实测：仅这两个控件随定义不同，其余 10 个两边一致）
4. 用 API 列出该台账的数据表，按结构确认子表（含「主合同」关联字段）和分类表（子合同类型选项来源）的 table id，回填 .env
5. 重拉 scripts/ledger/entity_map.json 和 category_map.json（正式表的选项与 record_id 和副本不同，旧文件不得沿用）
6. 归档并清空 data/state.json（副本的幂等状态不得带到正式台账）
7. 跑 py scripts/entry.py check 全绿后，先挑一张单 --dry-run 验证，通过后才允许正式 entry
```

切换完成前技能继续写副本；切换后历史行不迁移。
