# 合同台账录入

法务在自己的环境里**手动**跑一张合同审批：传入审批单上能看到的单号（如 `202609090050`），技能解析成实例，抽出表单和合同 Word 标题，写入台账**副本**。

同一张审批只建一次行。已经建过的单号会直接返回已有记录，不会再占一个编号。驳回后的空号由法务在台账里人工作废，技能不回收。

副本验收通过之前不要把 `.env` 里的台账 token 换成正式台账。

本技能**不**轮询、**不**发飞书消息、**不**把 Word 转 PDF、**不**盖水印、**不**下载风险报告附件。同意审批只在用户确认审批意见之后进行，而且只同意绑定使用人自己的当前待办。

## 安装

本机需要 **Python 3.11**。Windows 用 `py`，macOS 把下文的 `py` 换成 `python3`。

1. 探测：`py --version`。不是 3.11 就停下来，不要擅自安装系统软件。
2. 把本文件夹放进平台 skills 目录（zcode / Cursor / Hermes 相同）。
3. 复制 `.env.example` 为 `.env`，向用户索取并填写 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`。审批 code 和台账副本坐标已经预填，缺了不要硬跑。不要把密钥写进对话或提交到 git。
4. 安装依赖：`py -m pip install -r requirements.txt`（Windows 会一并装 pywin32，用于 `.doc` 自动转换）。外网不通时加 `-i http://docker-proxy.xgate.com/simple`。
5. 绑定使用人：向用户要**手机号或个人邮箱**（只要一项）。然后执行 `py scripts/entry.py bind-user --mobile <手机号>` 或 `--email <邮箱>`。把返回的 `bound: true` 告诉用户即可。**交付包已预置放行白名单**（全体授权使用人，4 个 user_id）：每台机器首次绑定也只能绑白名单内用户，绑定其他人（含管理员账号）会被拒绝，需管理员执行 `bind-user --add` 显式新增。绑定、换绑、拒绝、放行都追加写 `data/bind_audit.jsonl`（手机号/邮箱只落掩码，user_id 与时间一并记录）。不要把手机号、邮箱写进对话以外的文件（审计日志里只允许掩码形态），不要提交 `.env`。查不到就提示检查 `contact:user.id:readonly` 已发版，且该账号在应用通讯录权限范围内。
6. 自检：`py scripts/entry.py check`。`approver` 一项为已绑定后，放行才可用；未绑定时录入台账仍可用。

飞书自建应用需要这些权限，改完要**创建版本 → 发布 → 管理员审批**后才生效：

- `approval:approval.list:readonly`（按单号查实例）
- `approval:approval:readonly`（读实例和附件）
- `bitable:app`（读字段、查主合同编号、新增台账行）
- `contact:user.id:readonly`（安装时按手机号或邮箱反查使用人）
- `approval:task`（用户确认审批意见后同意其待办）

应用还要被加为这份台账副本的协作者。审批定义要对应用可见。

后台页面 id `7680902134576975065` 只出现在审批后台的网址里，**不要传给任何 API**。API 用的是审批定义 code `5D8E981F-1D5E-4C8E-9EA4-5E146B26F890`。

## 运行

在技能目录下执行。标准输出是一行 JSON。`ok` 不是 `true` 时，把 `error` 用自然语言转告法务，不要贴堆栈，不要复述密钥。

```
py scripts/entry.py check
py scripts/entry.py bind-user --mobile 13800138000
py scripts/entry.py bind-user --add --mobile 13800138000
py scripts/entry.py entry 202609090050 --dry-run
py scripts/entry.py entry 202609090050
py scripts/entry.py release 202609090050 --comment "合同编号：BTSP202610099"
```

- `check`：飞书令牌能否取到、审批 code、台账 app_token、主表/子表/分类表 id 是否都在、能否拉到主表字段、`entity_map.json` 和 `category_map.json` 是否在、使用人是否已绑定（含放行白名单人数）。未绑定不导致 `check` 失败。
- `bind-user`：反查 `user_id` 并写入 `.env` 的 `FEISHU_APPROVER_USER_ID`（类型 `user_id`）。这台电脑之后都以该法务的身份同意审批。白名单为空时首次绑定自动初始化；交付包已预置全体授权使用人，每台机器首绑也只能绑定白名单内用户。之后换绑白名单外的用户会被拒绝，报错里会提示由管理员 `bind-user --add` 显式新增。所有绑定尝试（含被拒）都记入 `data/bind_audit.jsonl`。
- `entry <单号> --dry-run`：单号定位、读表单、下载并解析 docx、校验我方主体选项和分类记录都做，**不**调用新增或更新，**不**放行。`contract_no` 为 `DRYRUN`。
- `entry <单号>`：校验通过后写入台账。主合同回读「合同编号（以此为准）」，子合同回读公式字段「子合同编号」（创建响应里常已有；没有则最多等 30 秒）。**不在这一步同意审批。**
- `release <单号> --comment`：只用在用户已经确认审批意见之后。意见全文必须包含本次合同编号，且绑定使用人须在本机放行白名单内。同意该使用人自己的一条当前待办，意见写入审批意见，不改表单控件。成功后追加审计行。

`entry` 成功后看 `release` 字段，再决定要不要问用户：

| `release` | 你要做的事 |
|---|---|
| `pending_confirm` | 把 `proposed_comment` 原文给用户看，请其确认或补充意见。用户只补充了别的话时，把「合同编号：…」那一行保留，后面接上用户的话，合成一段后再问一次「按这段放行吗」。用户明确同意后，才执行 `release`，`--comment` 用确认后的全文。用户没点头之前不要执行 `release`。 |
| `skipped` | 台账已经写好。把 `release_reason` 用自然语言转告，不要放行。 |
| `done` | 这张单已经放行过。不要再问，也不要再执行 `release`。 |

可选环境变量 `LEDGER_WORK_DIR` 改数据目录，默认是技能内 `data/`（幂等状态 `state.json`、审计日志 `bind_audit.jsonl`）。同一张单放行成功后状态里会记下 `released`，再次 `release` 不会重复同意。

## 写入什么

主合同（标题里没有下面四类词）写入主表，合同类型固定为「主合同」：

- 合同名称 = Word 首页标题
- 我方主体 = 审批签约主体全称映射成的简称，必须和台账选项逐字一致
- 相对方主体（全称）、合同金额、合同摘要（审批「概述」）

子合同不进主表。标题先匹配：

| 标题含有 | 写入 | 分类 |
|---|---|---|
| 补充协议、补充合同 | 子表 | 补充协议 |
| 终止协议、解除协议、解约协议 | 子表 | 终止协议 |
| 结算单、结算协议、结算对账单 | 子表 | 结算单 |
| 执行单、执行确认单 | 子表 | 执行单 |

子表只写：主合同关联（父行 record_id）、子合同类型（分类表一条 record_id）、我方主体、相对方、金额、摘要。

不写：合同编号（自动编号或公式，只回读）、合同编号 BT/N、公式列、双向关联以外的查找引用、父记录、合同属性、签订日期、归档/截止日期、扫描件、台账备注、复选框、附件。审批表单控件也不改；合同编号只出现在确认后的审批意见里。

父合同编号从 Word 里找：先标题，没有再看首页正文。形式是 `BTSP` 加连续 9 到 10 位数字；后面的 `-BC` / `-ZZ` / `-JS` / `-zx` 后缀截掉。例如 `BTSP202307049-BC01` 的父号是 `BTSP202307049`。唯一命中才到主表查那一行：自动编号列不能筛选，改为「合同名称唯一值」包含该编号，且必须只命中一行。

我方主体全称对不上映射就停住。主表写简称；子表在简称上再套一层覆盖（目前只有兔竞 → 成都兔竞）。映射和分类 record_id 随副本变化，换副本要重拉，改 `scripts/ledger/entity_map.json` 和 `category_map.json`（文件里有「随副本变化，换副本重拉」）。

相对方：签约类型、客户名称、供应商名称里取先出现的一项，去掉 `｜` 后面的信用代码。三者全空时从合同 Word 的甲方/乙方抬头按「签约主体排除法」兜底（排除我方与自然人，须唯一，见 `ledger/contract_party.py`）；仍取不到则停住。有达人真实姓名时再追加达人，并追加达人企业名称。达人或关联了商单时再追加项目名称——但项目名称**不会单独**充当相对方（2026-10-26 生产案例：控件 id 与正式定义不一致致基底读空，项目名称冒充主体，已堵死）。用 `/` 拼起来。

合同标题取首页字号最大、且不是「xxx：」这种标签、长度至少 4 个字的那一行。整页都没有字号时，用第一个非空、非标签行。

附件 `.docx` 直接解析。旧版 `.doc`（文件头 `D0CF11E0`）会用**本机 Word 静默转换**成临时 `.docx` 再解析：转换只发生在本地临时副本，审批附件原件不动、用完即删；Word 以独立实例启动（只读、禁宏、不弹窗），45 秒超时自动强杀该实例并停住。本机不是 Windows、缺 pywin32、没装 Word、文件加密或损坏时停住，提示手动另存为 `.docx` 重新上传。其他非 Word 格式停住。

## 停住（不建行、不占号）

出现下面任一情况，技能停住，`error` 里是中文原因，不另发飞书消息：

- 按单号前 8 位日期，在前后几天里找到 0 条或不止 1 条审批
- 没有合同附件，或附件不是 Word 文档（`.doc` 会先经本机 Word 自动转换；转换不可用——非 Windows、缺 pywin32、未装 Word、加密或损坏——时停住，提示另存 `.docx` 重传）
- 抽不出标题
- 签约主体全称不在映射表里
- 相对方主体取不到：签约类型/客户/供应商全空，且合同 Word 里也无法唯一甄别签约对方（常见于审批定义控件 id 与 `widgets.py` 配置不一致）
- 映射出的简称不在目标表「我方主体」选项里
- 子合同找不到唯一父编号 `BTSP`，或主表里这个编号不是唯一一行
- 分类 record_id 已经不在分类表里
- 主合同编号或子合同编号 30 秒内没有生成，或编号回读接口异常（行若已建成，都会先记下 record_id，重跑幂等返回已有行，不再占新号）

使用人未绑定、不在本机放行白名单、不是当前待办审批人、待办多于一条，或审批意见里没有本次合同编号时，台账行保留，只是不放行。原因在 `release_reason` 或 `error` 里。白名单外的换绑在 `bind-user` 就被拒绝，不会写 `.env`。

已经录入过的实例不会停住，会返回上次的 `record_id`。要重跑必须先删掉 `data/state.json` 里对应的 `instance_code`。旧副本上的状态不要拿来挡这次。
